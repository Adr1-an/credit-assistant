# Уточнения к модели скоринга после решений БА

Статус: согласовано владельцем продукта. Полная модель баллов утверждена — `scoring-model-v1.docx`; при расхождении с этим файлом главный — документ модели.

## 1. Срок выхода на прибыль — прогноз клиента, не факт

Источники: `question-sets.json → start.breakEven / location.breakEven → field: expectedBreakEvenMonths`. Его значение основано на словах заявителя. **Не начислять за него баллы, включая ранее предложенные 6 баллов `IDEA_NORMAL_AFFORDABILITY` для стартапа.** Не подменять им проверенные обороты и коэффициент покрытия платежа.

Допустимо только **информационное** сравнение с `industries.json → typicalBreakEvenMonths`:

- если одно из двух значений `null`, равно 0 или не является положительным целым, ничего не вычислять;
- иначе `differenceMonths = expectedBreakEvenMonths - typicalBreakEvenMonths`;
- `< 0`: «По вашему прогнозу окупаемость быстрее отраслевого ориентира на N мес.»;
- `= 0`: «Прогноз совпадает с отраслевым ориентиром»;
- `> 0`: «По вашему прогнозу окупаемость медленнее ориентира на N мес.»;
- отдельно помечать «Прогноз клиента, не подтверждён» и «Отраслевой ориентир синтетический»;
- **баллы не изменяются**.

## 2. Пекарня без кредитной истории (тестовый клиент T06)

`BUSINESS = 20`, `OWNER = 16`, `IDEA = 0`, `INDUSTRY = 7` → **43 балла / YELLOW / MANUAL_REVIEW**. Прогноз клиента `expectedBreakEvenMonths = 11`, ориентир отрасли `10.71` = 18, разница −7 месяцев — **баллы за это не начисляются**. Раньше в черновике модели за прогноз давалось 6 баллов (было 49), их убрали.

Это не проверка состоятельности будущего бизнеса: личный кредитный отчёт и отрасль не доказывают будущую выручку.

## 3. Завершённое банкротство

- `inProcedure = true`, стадия действующая: текущий `STOP` — команда ранее обсуждала как внутренний стоп-фактор; это допущение модели.
- `inProcedure = false`, `stage = COMPLETED`, `completedAt` менее пяти лет до даты оценки: `MANUAL`, не `STOP` и не штрафные баллы.
- пять лет истекли: по одному пятилетнему правилу `NONE`; общий скоринг может учитывать другие независимые факторы.
- дата отсутствует/ответ противоречив: `MANUAL`, не автоматизировать юридический вывод.

По ст. 213.30 Закона № 127-ФЗ пятилетнее последствие для кредитов — обязанность указать банкротство при получении кредита/займа, не абсолютный запрет на кредит. Для признанного банкротом ИП ст. 216 содержит дополнительные пятилетние ограничения на предпринимательскую деятельность и **исключения** (п. 5). Данных текущей заглушки недостаточно, чтобы однозначно решить, действуют ли эти ограничения в конкретном случае. Поэтому `MANUAL`.

Источники: https://www.consultant.ru/document/cons_doc_LAW_39331/15bac90772e695baab0ffa86106dfd11c02e7802/ и https://www.consultant.ru/document/cons_doc_LAW_39331/172be73862055bd14886b44f702a4f7fceb7f94c/ .

## 4. Налоговая история

Фактор «недавно закрыл налоговый долг» **не утверждён**. Историю погашения в `/fns/tax-debt/{inn}` не добавлять. Налоговый фактор учитывает текущую задолженность по `hasDebt`, `debtAmount`, `asOf`.

## 5. Сверка паспорта — согласованный вариант Б

`mocks-contract.md → POST /passport/check` принимает поля `Passport.series`, `number`, `lastName`, `firstName`, `middleName?`, `birthDate`, `issueDate`; сверяет с **независимой синтетической записью**. `valid=false` с установленной причиной → `STOP`; действительный паспорт с несовпадением / неизвестными данными владельца → `MANUAL`; полный матч → `NONE`. Невалидный запрос или недоступность источника не является автоматическим отказом. Форматы и таблица тестов — в `mocks-contract.md` и `passport-test-cases.md`.

## 6. Где сотрудник видит прогноз и отраслевое сравнение

Добавлено *необязательное* `openapi.yaml → StaffApplicationCard.breakEvenComparisons[]` с `goalIndex`, `goalType`, `questionId`, `okvedCode`, `clientMonths`, `industryMonths`, `differenceMonths`, `sourceType`, `dataAsOf?`, `text`.

- Для каждого `GoalsData.goals[i]` с типом `START_BUSINESS` или `NEW_LOCATION` найти `answers[].questionId`, соответственно `start.breakEven` или `location.breakEven`; использовать только положительное целое `value`.
- Отраслевой ориентир: `industries.json → industries[].typicalBreakEvenMonths` по согласованному ОКВЭД (для стартапа — `start.okved`; для действующего бизнеса — `okvedMain.code`) с fallback группы по правилу отраслевого справочника.
- Если нет любого положительного срока/отрасли — **не добавлять элемент** в массив (возвращать пустой массив, если нет элементов).
- `differenceMonths = clientMonths - industryMonths`; в `text` указать «по прогнозу клиента» и, для `sourceType=SYNTHETIC`, «синтетический отраслевой ориентир».
- Текст точно: `По прогнозу клиента окупаемость быстрее синтетического отраслевого ориентира на N месяцев` (`медленнее` при `differenceMonths > 0`; при 0 — `Прогноз клиента совпадает с синтетическим отраслевым ориентиром`). Для `sourceType = OFFICIAL` вместо «синтетического отраслевого ориентира» — «отраслевого ориентира». Слово «месяц» по числу: 1 месяц, 2–4 месяца, 5+ месяцев (11–14 — месяцев).
- T06: `clientMonths=11`, `industryMonths=18`, `differenceMonths=-7` → `…быстрее синтетического отраслевого ориентира на 7 месяцев`. **Никаких баллов.**
- Эти поля только для сотрудника и не добавляются в `Application`, который видит клиент. ИИ не рассчитывает сравнение; результат выдаёт сервер по обычным правилам.

## 7. Человек без бизнеса (стартап) — одно правило

Согласовано владельцем продукта. Заменяет более ранние формулировки о том, что стартап «всегда жёлтая зона».

- Система обрабатывает заявку стартапа до конца: проверки, смета, баллы, предложение.
- **Автоматическое одобрение** возможно, только если одновременно: запрошенная сумма не выше порога `STARTUP_AUTO_APPROVE_LIMIT` и личная кредитная история владельца хорошая.
- Во всех остальных случаях — `MANUAL_REVIEW` с готовой рекомендацией системы.
- Стоп-факторы действуют как обычно.
- Порог `STARTUP_AUTO_APPROVE_LIMIT = 200000` и точное определение `GOOD_BKI` — `scoring-model-v1.docx`, раздел 6. Порог хранится в настройке сервера, а не в коде.
- Фронт показывает только ответ сервера и ничего не вычисляет сам.

## 8. Флаги (`Score.flags`)
