# Продуктовые требования и границы системы

Версия 1.0 · 25.10.2026 · Основа — контракт 1.1 (`contract/`). Если документы расходятся, верен контракт.

**Продукт.** «Умный кредитный кабинет предпринимателя» — сайт, где ИП приходит не за кредитом, а с задачей бизнеса («открыть второй цех»). Система сама собирает смету, оценивает риск по точным данным и предлагает пакет продуктов. Решение и все цифры считают правила, ИИ только помогает понять клиента и объяснить договор.

## 1. Проблема и цель

**Проблема.** Предприниматель не знает, какой продукт ему нужен и сколько денег просить. Отказы приходят без объяснений, договор непонятен, а когда выручка падает, банк реагирует только на просрочку.

**Цель.** За одну заявку:
- превратить задачу клиента в смету;
- честно оценить риск;
- выдать понятное предложение или объяснимый отказ;
- после выдачи помогать, а не только взыскивать.

## 2. Пользователи и роли

| Роль | Кто это | Что может |
| --- | --- | --- |
| ИП | Индивидуальный предприниматель, в том числе не клиент Альфа-Банка | Подать заявку, загрузить выписку или заполнить анкету, описать цель, поправить смету, выбрать предложение, подписать договор, получать уведомления после выдачи |
| Человек без бизнеса | Хочет открыть ИП | То же, но без выписки; выбирает вид бизнеса (ОКВЭД) |
| Сотрудник банка | Кредитный специалист | Видит все заявки (спорные сверху), карточку с баллами и рекомендацией; одобряет, меняет условия, запрашивает данные, отказывает |

Входа по паролю нет: клиент работает с заявкой по её номеру, сотрудник — на странице `/staff`.

## 3. Границы системы

**Входит в продукт:**

| Часть | Что делает |
| --- | --- |
| Путь клиента | Паспорт и ИНН → согласие → 6 проверок → выписка или анкета → цель (чат с ИИ или форма) → смета → решение → предложения → договор → подпись кодом |
| Оценка риска | 11 факторов, 100 баллов, три зоны, стоп-факторы и ручная проверка |
| Кредитное решение | Смета по «кубикам», подбор продуктов, ставки, безопасный платёж, варианты «Начать меньше» и «Без отсрочки» |
| Кабинет сотрудника | Список заявок, карточка, рекомендация, решения, история |
| После выдачи | График платежей, раннее предупреждение при падении выручки, рост лимита при росте |

**Смоделировано (заглушки, синтетические данные):**
- реестр ИП (ЕГРИП);
- налоговая задолженность;
- бюро кредитных историй;
- приставы (ФССП);
- реестр банкротств;
- проверка паспорта;
- выдача денег и подписание (код показывается на экране, без SMS).

**Не входит:**
- настоящие запросы во внешние системы;
- реальная выдача денег;
- вход по паролю;
- юридически значимый договор;
- конструктор «Проверить свой бизнес» (решено не делать);
- погашение долей эквайринга (продукт `REVENUE_BASED_LOAN` зарезервирован на будущее).

## 4. Где ИИ, а где правила

| Задача | Кто делает | Если ИИ недоступен |
| --- | --- | --- |
| Понять цель из текста клиента, задать уточняющие вопросы | ИИ | Форма с теми же вопросами |
| Подсказать ОКВЭД | ИИ (клиент подтверждает) | Поиск по справочнику |
| Подсказать категорию непонятной строки выписки | ИИ, только для отображения | Категория «прочее» |
| Объяснить договор своими словами | ИИ | Готовые ответы «Что будет, если…» |
| Сводка для сотрудника | ИИ | Список причин из баллов |
| Проверки, баллы, зона, смета, ставки, решение | **Только правила** | — |

ИИ ничего не решает и не называет сумм. Текст клиента для ИИ — данные, а не команды.

## 5. Функциональные требования

| № | Требование | Где правило |
| --- | --- | --- |
| FR-1 | Создать заявку по паспорту и ИНН; при уже открытой заявке вернуть её | `openapi.yaml`, `statuses.md` |
| FR-2 | После согласия выполнить 6 проверок и разложить их по корзинам: стоп-фактор, минус баллы, к сотруднику | `mocks-contract.md` |
| FR-3 | При сбое сервиса сохранить заявку и дать повторить проверки | `statuses.md` |
| FR-4 | Принять выписку CSV, отделить выручку от прочих поступлений, посчитать 12 завершённых месяцев | `mocks-contract.md` |
| FR-5 | Без выписки принять анкету; такая заявка всегда идёт к сотруднику | `scoring-model-v1` |
| FR-6 | Определить цель через чат с ИИ или форму; после 2 неудачных попыток — кнопки целей и передача сотруднику | `llm-contract.md`, `statuses.md` |
| FR-7 | Собрать смету по целям из выписки, ответов клиента и правил; дать её поправить | `product-rules-v1.md` |
| FR-8 | Посчитать 11 факторов с текстом причины и зону | `scoring-model-v1` |
| FR-9 | Стартапу автоодобрение только до 200 000 ₽ при хорошей кредитной истории | `scoring-model-v1`, раздел 6 |
| FR-10 | Построить до 3 предложений с безопасным платежом | `product-rules-v1.md`, раздел 4 |
| FR-11 | Показать договор с пояснениями, сводку из 3 пунктов, готовые ответы; подпись кодом | `product-rules-v1.md`, раздел 7 |
| FR-12 | Отказ — с советами (до 3) и без внутренней формулы | `product-rules-v1.md`, раздел 6.2 |
| FR-13 | Кабинет сотрудника: список, карточка с баллами, рекомендация, 4 решения, история | `openapi.yaml` (`/staff`) |
| FR-14 | После выдачи: график, раннее предупреждение, рост лимита | `product-rules-v1.md`, раздел 8 |
| FR-15 | Демо: список тестовых клиентов и их выписки | `tests/` |

## 6. Нефункциональные требования

| № | Требование |
| --- | --- |
| NFR-1 | Весь проект запускается одной командой в Docker |
| NFR-2 | Без ИИ основной сценарий работает полностью |
| NFR-3 | ИИ подключается по стандарту OpenAI и меняется тремя настройками без правки кода. Основной вариант — GigaChat через прокси gpt2giga; без ключа ИИ выключен и работает форма |
| NFR-4 | Одинаковые данные всегда дают одинаковый результат (баллы, смета, предложения) |
| NFR-5 | Клиент никогда не видит баллы и формулы |
| NFR-6 | Внешний сервис отвечает не дольше 5 секунд, иначе считается недоступным |
| NFR-7 | Все пороги и ставки — в настройках сервера, не в коде |
| NFR-8 | Описание API — OpenAPI и Swagger на `/docs` |
| NFR-9 | Все данные синтетические; сторонние компоненты и смоделированные интеграции перечислены в `THIRD_PARTY_NOTICES` |

## 7. Допущения

- Все ИНН, паспорта, выписки и отраслевые цифры вымышлены.
- Ставки, лимиты, веса баллов и пороги зон — допущения команды для прототипа, **не** условия Альфа-Банка. Основа ставок — ключевая ставка Банка России 14% (на 23.10.2026).
- Дата оценки в демо зафиксирована: 24.10.2026.
- Сверка паспорта с записью не доказывает, что паспорт в руках у заявителя.
