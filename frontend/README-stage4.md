# Этап 4 — уточняющие вопросы и смета

Это продолжение этапа 3. Добавлено без изменения библиотек (package.json остался тем же).

## Быстрая проверка на Mac

1. Скопируйте патч в существующую `~/Downloads/frontend/` или распакуйте полную сборку поверх папки.
2. В каталоге `~/Downloads/frontend` выполните `npm run dev`. Если зависимости уже установлены и файл `package-lock.json` на месте, **повторно запускать `npm install` не нужно**.
3. Откройте:
   - `http://localhost:3000/preview/goals` — выбор цели; после выбора доступна кнопка «Продолжить к вопросам»;
   - `http://localhost:3000/preview/questions` — макет пошаговой формы для цели «Открыть новую точку»;
   - `http://localhost:3000/preview/estimate` — редактируемая смета с **синтетическими демонстрационными суммами**.
4. После остановки Vite (`Ctrl+C`) выполните `npm run typecheck` и `npm run build`.

## Поведение в реальной заявке

- Экран выбора цели и вопросов открывается **только** по `Application.nextAction = SET_GOALS`. Вопросы читаются из `GET /api/question-sets`. UI отображает по одному вопросу, выбор «не знаю» только при `unknownAllowed`, проверяет типы введённых ответов. Для бизнеса без ИП ОКВЭД ищется запросом `GET /api/okved?query=...`.
- `PUT /api/applications/{id}/goals` предусмотрен и строго типизирован сгенерированным `GoalsData`, но отправка **осознанно заблокирована**, поскольку OpenAPI по-прежнему описывает `GET /question-sets` как просто `object`, а разделение `inventory.amount` ещё не опубликовано. После обновления договора команды разрешаем отправку, не придумывая идентификаторов. В текущем варианте цель INVENTORY показывает предупреждение об устаревшем контракте.
- Экран сметы открывается только при `nextAction = REVIEW_ESTIMATE` или `SUBMIT`. Получение: `GET /api/applications/{id}/estimate`, изменение: `PUT /api/applications/{id}/estimate`, отправка: `POST /api/applications/{id}/submit`. Типы `Estimate`, `EstimateItem`, `EstimateUpdateRequest` получены из OpenAPI.
- Изменённые суммы не считаются на клиенте: после `PUT /estimate` отображается возвращённая сервером смета, затем отдельно запрашивается заявка для получения актуального `nextAction`.
- Кнопка отправки заявки включается только при `nextAction = SUBMIT`, если нет несохранённых изменений. Клиенту **не показываются** баллы и зоны.
- Ошибки: сообщение (`message`) из API, переходы — только по `nextAction`. Prism не хранит состояние заявок.

## Лицензии и установка

Новых зависимостей нет. Базовые компоненты написаны самостоятельно на React и CSS.

**Важно:** локальный `package-lock.json` не включён в архивы. Он уже создан на вашем Mac в `frontend/` — ни в коем случае не удаляйте и добавьте его в Git. После обновления API запустите `npm run api:generate`, затем `npm run typecheck`.

## Что необходимо получить от команды

1. Исправленный `openapi.yaml` с точной схемой ответа `GET /question-sets`.
2. Согласованный `question-sets.json` с **двумя отдельными вопросами** о том, что покупают, и о сумме, включая их настоящие `id`.
3. После этого можно безопасно активировать `PUT /goals` и переходить из вопросов к смете через ответ сервера.
