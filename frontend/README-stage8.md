# Этап 8 — подготовка к интеграции, без выдуманного Python-сервера

Этот этап добавляет **read-only** проверку доступности API, сравнение контрактов и список 21 краевого случая. Никаких изменений в клиентских маршрутах, запросах, статусах и расчётах не делается. Сценарии с созданием/подписанием заявок не запускаются автоматически: они требуют синтетических данных бэкенда.

## Что уже можно проверить на Mac

Все команды выполняются в каталоге `frontend/`, где расположен `package.json`.

1. Запустите `npm run dev` в первом Терминале. При работе с Prism запустите `npm run mock:api` во втором Терминале.
2. В третьем Терминале выполните:

```bash
npm run test:integration-tools
npm run api:contract-check
npm run api:smoke
npm run typecheck
npm run build
```

`api:smoke` проверяет только GET `/health`, `/question-sets`, `/demo/clients`, `/staff/applications` через **Vite-прокси `/api`**, не записывая данных. Если есть синтетическая заявка, можно также выполнить:

```bash
npm run api:smoke -- --application-id ВАШ-UUID-ИЗ-АДРЕСА
```

Проверка с Prism подтверждает формат и прокси, **но не сохранение заявки**.

## Подключение FastAPI человека 2

1. Уточните у человека 2, слушает ли сервер `/api/health` или `/health`. Из `README.md` команды известно `localhost:8000`, но префикс реального Python-приложения ещё не подтверждён.
2. Поместите обновлённый согласованный `openapi.yaml` **рядом с папкой `frontend/`** (путь `../openapi.yaml`). Он приоритетнее архивной копии в `frontend/contract/`. Вместе с ним обновите согласованный `question-sets.json` и локальные копии для самостоятельной сдачи.
3. В папке `frontend` создайте `.env.local` (или отредактируйте существующий):

```
API_PROXY_TARGET=http://localhost:8000
API_PROXY_STRIP_PREFIX=false
```

Строка `false` верна **только если FastAPI действительно принимает `/api/...`**. Если он принимает пути без префикса (`/health`, `/applications`), нужен `true`. Договоритесь об этом с человеком 2, не меняя адреса в React.
4. Остановите Vite (`Control+C`) и заново `npm run dev` — Vite читает настройки прокси при запуске. Prism останавливать необязательно, если Vite больше не направляет туда запросы.
5. Выполните `npm run api:smoke` и убедитесь, что ответы идут от FastAPI, а не Prism. Проверьте `npm run api:contract-check`, `npm run typecheck`, `npm run build`.
6. Проверьте вручную путь: `/` → `/apply` → `/applications/:id` → согласие → выписка или анкета → цели → смета → решение → предложение → договор → график платежей. На каждом шаге сверьте реальный `nextAction` и перезагрузите страницу.
7. Откройте `/staff`, выберите спорную заявку и сделайте тестовое решение с комментарием. Затем откройте **ту же заявку** как клиент и проверьте обновлённый статус.
8. Пройдите 21 сценарий в [`docs/edge-cases-21.md`](docs/edge-cases-21.md) по мере появления синтетических данных.

## Что пока не готово по текущей версии контракта

- `GET /question-sets`: вместо конкретной схемы ответа описан просто `object`; форма не может считаться окончательно подключённой.
- `inventory.amount`: старый общий вопрос ещё не разделён на «Что закупаете» и «На какую сумму». Новые `id` должны быть согласованы командой.
- Повторная заявка: не описано, каким ответом API сообщает, что вернул существующую заявку, и как фронт показывает «Продолжить?».
- Передача сотруднику после двух неудачных уточнений ИИ: согласованного API-операции пока нет.
- В концепции ИНН ищется в реестре уже при вводе, но по текущему OpenAPI внешние проверки начинаются только после согласия. До согласования поведение не меняем.
- Имя Docker-сервиса Python и маршрутизация префикса `/api` внутри контейнеров должны быть подтверждены людьми 2 и 4.

Всё это **блокеры части сквозного сценария**, а не повод «сделать вид», что всё работает. Ничего не добавляйте в OpenAPI наугад.

## Docker и lock-файл

Существующий `Dockerfile` использует `npm ci`, поэтому **в сдаваемой папке frontend обязателен настоящий `package-lock.json`**. Если вы распаковали полный архив, а lock отсутствует, сделайте `npm install` на Mac, добавьте lock в Git и проверьте `npm ci`. Патч этапа 8 меняет только скрипты в `package.json` и не требует добавлять библиотеки.

Docker nginx требует `BACKEND_UPSTREAM` — значение в `docker-compose.yml` определяет человек 4 после согласования имени сервиса и префикса API с человеком 2. Не подменяйте `BACKEND_UPSTREAM` догадкой.

Перед сдачей проверьте `npm audit` (не используйте `npm audit fix --force` без проверки зависимостей) и запустите контейнеры совместно с командой.
