# Этап 6 — договор, подпись, график платежей

**Готово:** клиентские экраны договора и сопровождения после выдачи, с загрузкой только по `nextAction` API.

## Как запустить на Mac

Из корня `frontend/`:

```bash
npm install               # только если ещё нет node_modules
npm run dev
```

`npm install` создаёт `package-lock.json` — **добавьте его в Git и не удаляйте**. На последующих этапах, если зависимости не меняются, установка не нужна.

Предпросмотр без Python-сервера:

- http://localhost:3000/preview/contract — договор, важные пункты, готовые вопросы, чекбокс и демо-код;
- http://localhost:3000/preview/after-issue — график платежей, уведомления и демо-кнопка.

В предпросмотре **все данные синтетические**. Запросы в API и реальная подпись отключены. Для работы с настоящей заявкой путь `/applications/:id` после ответа сервера с `nextAction: SIGN` показывает договор, а при `nextAction: NONE` и `status: ISSUED` — график. Эти переходы не высчитываются на сайте.

## API — только через `/api`

**Обязательно (`must`):**

- `GET /api/applications/{id}/contract` — договор (пункты, `plainText`, `important`, 3-пунктная сводка, FAQ);
- `POST /api/applications/{id}/sign/code` — получает шестизначный код и показывает его **на экране**;
- `POST /api/applications/{id}/sign` — `{ code, understood: true }` и новый `Application`;
- `GET /api/applications/{id}/schedule` — график после выдачи.

**Желательно (`should`):**

- `GET /api/health` — доступность ИИ для свободных вопросов;
- `POST /api/applications/{id}/contract/ask` — готовый FAQ (`questionId`, без ИИ) или текст (`text`, с ИИ);
- `GET /api/applications/{id}/notifications` — уведомления;
- `POST /api/applications/{id}/notifications/{notificationId}/choose` — выбранное действие, новая `Schedule`;
- `POST /api/demo/applications/{id}/advance-month` — только для тестовых заявок (демо-сценарий).

Ответы о договоре сопровождаются подписью: «Пояснение справочное и не заменяет юридическую консультацию». При `aiAvailable: false` или ошибке `AI_UNAVAILABLE` доступен готовый FAQ. Ошибки показывают серверное `message` и проверяют `code`; `CODE_EXPIRED` требует запросить код повторно.

## Самостоятельная проверка

1. Откройте `/preview/contract`: раскройте юридический текст, найдите «Важно», отметьте «Понятно», нажмите «Показать код подписи» (только демонстрационный). Подпись в предпросмотре недоступна.
2. Откройте `/preview/after-issue`: проверьте график, задолженность и подсказки. Кнопки, которые изменяют серверное состояние, в предпросмотре выключены.
3. Проверьте адаптивность: ширина браузера 375 px.
4. Выполните `npm run typecheck` и `npm run build` после установки зависимостей.
5. Когда FastAPI будет готов, пройдите путь `CHOOSE_OFFER → SIGN → NONE + ISSUED`, проверьте `CODE_INVALID`, `CODE_EXPIRED`, `AI_UNAVAILABLE`, пропавшие уведомления и 409 `INVALID_STATUS`. Prism не хранит состояние заявки — это не полноценный end-to-end тест.
