# Умный кредитный кабинет предпринимателя — фронтенд

React 19 + TypeScript + Vite. Рабочие экраны находятся в `src/pages/`; старые работающие компоненты и макеты предпросмотра сохранены. Клиентская часть доступна по `/`, `/apply`, `/applications/:id`, сотрудник — `/staff`, демонстрационные страницы — `/preview`. Входа и паролей нет. Вся работа с API происходит только по относительным `/api/...`.

**Источник истины:** в полном репозитории `contract/openapi.yaml`, `contract/question-sets.json`, `contract/statuses.md`, `contract/product-rules-v1.md` и `contract/llm-contract.md`. Для самостоятельной сборки фронта актуальные копии первых двух файлов находятся в `frontend/contract/`. См. [API-CONTRACT-AUDIT.md](API-CONTRACT-AUDIT.md) с таблицей исходных и исправленных запросов.

## Запуск на Windows без Docker

1. Установите Node.js 22.x с npm. Если терминал не видит `node`, откройте новый PowerShell.
2. Из полного архива проекта перейдите в `frontend`:

   ```powershell
   cd путь\к\проекту\frontend
   npm install
   ```

   `npm install` создаёт **реальный `package-lock.json`** для зафиксированных версий. Его нужно добавить в Git; не добавляйте `node_modules` и `dist`.
3. Запустите FastAPI в отдельном окне по инструкции команды на `http://localhost:8000`. В полной конфигурации backend принимает URL вида `/api/health`.
4. В PowerShell во фронтенде:

   ```powershell
   Copy-Item .env.example .env.local
   npm run dev
   ```

5. Откройте **http://localhost:3000**. Для проверки формального соответствия и сборки:

   ```powershell
   npm run api:contract-check
   npm run test:integration-tools
   npm run api:smoke
   npm run typecheck
   npm run build
   ```

Vite проксирует `/api` в `http://localhost:8000`, не удаляя префикс. Для отдельного тестирования со Stoplight Prism настройте `.env.local`: `API_PROXY_TARGET=http://localhost:4010`, `API_PROXY_STRIP_PREFIX=true` и запустите `npm run mock:api` в отдельном окне. **Prism не сохраняет состояние**; сквозной маршрут заявки проверяйте с FastAPI.

## Реальный клиентский сценарий

1. Главная загружает синтетических клиентов из `GET /api/demo/clients`. Кнопка заполняет анкету; выписка скачивается с `/api/demo/statements/{inn}`.
2. Анкета отправляет паспорт, ИНН и `hasBusiness` в `POST /api/applications`. HTTP 201 создаёт заявку, HTTP 200 предлагает продолжить открытую с датой `createdAt`. Для стартапа личный ИНН запрашивается в интерфейсе сразу, потому что он понадобится при согласии для шести проверок.
3. Экран `/applications/:id` загружает заявку из API и выбирает **исключительно** по `nextAction`. После согласия показывает только полученные от сервера результаты `checks[]`; для `RETRY_CHECKS` предлагает повторение, для `WAIT` — обновление.
4. При `UPLOAD_STATEMENT` загружается выписка либо анкета. При `SET_GOALS` вызываются `GET /api/health` и `GET /api/question-sets`: если ИИ недоступен — форма; если доступен — диалог с `ASKING` / `SUMMARY` / `ESCALATED`. Готовая сводка подтверждается `PUT /goals`, при непонятой цели возможен `POST /handoff`. Форма и ИИ не вычисляют смету самостоятельно.
5. При `REVIEW_ESTIMATE` / `SUBMIT` можно исправить суммы и отправить заявку; при `CHOOSE_OFFER` — выбрать предложение, при `SIGN` — изучить договор, готовые вопросы и подписать **кодом, показанным на экране**, без SMS.
6. При `INFO_REQUESTED` можно отправить уточнение; при `REJECTED` показаны причина и советы из API; после `ISSUED` доступны график, уведомления и «Перемотать месяц».
7. Кабинет `/staff` показывает список и карточку заявок, проверки, баллы, флаги, смету, окупаемость и решения. Баллы/формулы не показываются клиенту. Для переданных по непонятной цели заявок сотрудник должен указать условия, если одобряет заявку.

## Docker

Из корня полного репозитория настройте сервис `frontend` со сборкой `./frontend` и портами `3000:3000`. `frontend/Dockerfile` собирает Vite-приложение и запускает nginx на порту **3000** с прокси `/api/` на `http://backend:8000`. Сервис `backend` должен существовать в той же Docker-сети.

Для воспроизводимой установки нужен `package-lock.json`. В изолированном окружении подготовки этого архива npm-реестр недоступен, поэтому lock не удалось создать и полноценный `npm run build` выполнить нельзя. Dockerfile временно использует `npm install` при отсутствии lock; после установки зависимостей и сохранения lock автоматически применяется `npm ci`. Это **ограничение проверки**, а не утверждение о готовности сборки.

## Проверки и ограничения

- Тесты инструментов: `node --test tests/*.test.mjs` (не требуют сервера).
- Аудит контракта: `node scripts/contract-audit.mjs`.
- `npm run api:smoke`: проверки реального GET через Vite; при неработающем сервере ожидаемо сообщит о проблеме.
- `src/api/schema.d.ts` создаёт `npm run api:generate` из OpenAPI. Схемы не редактируются вручную.
- Для полноценной приёмки необходимы запущенный FastAPI и реальные тестовые сценарии `tests/` из полного репозитория. Локальные демонстрационные данные на страницах `/preview` не используются в рабочем API.
- В согласованном OpenAPI `DialogState` нет поля `assistantText`, хотя оно есть в `contract/llm-contract.md`. Фронтенд отображает текст из `DialogState.messages`, не предполагая отсутствующее поле. Согласование `assistantText` с владельцем контракта остаётся открытым вопросом.
